# In-game co-op integration

The Windows mod should let players launch Project Silverfish through Steam and choose **Singleplayer** or **Multiplayer** on the stock title screen. Multiplayer provides native Host and Join menus. The host chooses a Direct IP UDP port and an optional password. The guest enters the host's IP address and port, supplies a password if required, and selects or creates a character in that host campaign. The menu shows connection, admission, world loading, reconnect, and save status.

The [18 locked rules](DESIGN.md) apply to every milestone. Moving the controls into the game leaves the host responsible for the shared world, wallet, travel, rewards, and committed campaign. Direct IP is the first transport. Steam Invite remains deferred and will use the same campaign identities and admission rules.

## Delivery milestones

1. **Title menu to isolated co-op stage.** Add the title entry in the matched staged build. Host and Join call the current supervisor through a private, structured handoff. The supervisor reserves the campaign or profile, passes an isolated prelaunch user directory, and reports when the requested host or guest is ready. Start with two staged processes. Verify one click produces one launch, a rejected or cancelled request leaves the title usable, and stock single-player buttons still load their own data. Hash the original save directory before and after.
2. **Steam startup and complete in-game controls.** Use the stock Steam title and multiplayer menus for hosting a new or saved campaign, direct join, character selection, reconnect, and exit. Qualify the controls in a stock-layout replica first, then verify the Steam launch. On two separate PCs, verify a player-selected port, joining with and without a password, movement, automatic reconnect after packet loss, and host restart. Include a mismatched build, a wrong password, and a cancelled connection.
3. **In-process session supervisor and transport.** Give the shipped Windows mod runtime ownership of admission, reconnect reservations, Unreal relay management, and state reporting. Start and stop co-op from the running Steam game process. Keep the transport on its worker thread and apply Unreal mutations on the game thread. Bind raw Unreal gameplay to loopback. Repeat admission, timeout, network-loss, active roster, hot join, zone travel, and wipe checks on two PCs.
4. **Native campaign persistence.** Move the checkpoint coordinator, campaign lock, and recovery into the native runtime. Preserve stock serialization for typed native state and commit a versioned manifest that binds the host world, guests, wallet, checkpoints, and item and reward receipts to one generation. Keep a verified backup and resume the last complete commit after interruption. Test existing co-op campaign migration, termination during each commit phase, recovery after a partial write, and replay of a previously settled transaction.
5. **Keep mode selection save-safe.** Qualify the running game's campaign storage routing before enabling mode switching. Verify cached engine paths, menu listing, existence, load, save, autosave, delete, restore, shutdown, and Steam Cloud for each mode across repeated mode changes and crashes. Preserve the original game's local settings across the same transitions.
